## 三、数据模型

### 3.1 实体定义

```typescript
// ==================== User ====================
interface User {
  id: number
  walletAddress: string      // 主键，唯一
  name?: string
  email?: string
  avatar?: string
  bio?: string
  role: 'customer' | 'agent' | 'both'  // 【Assumption】用户可同时是客户和代理人
  isVerified: boolean
  createdAt: string
  updatedAt: string
}

// ==================== Agent ====================
interface Agent {
  id: number
  userId: number             // FK -> User
  title: string              // 服务标题
  description: string
  category: string           // 服务类别
  subcategory?: string
  location: Location
  services: Service[]
  pricing: Pricing[]
  availability: Availability
  rating: number             // 平均评分 0-5
  reviewCount: number
  completedJobs: number
  responseTime: string       // 【Assumption】如 "< 1 hour"
  languages: string[]
  tags: string[]
  isActive: boolean
  createdAt: string
  updatedAt: string
}

interface Service {
  id: number
  name: string
  description: string
  duration: number           // 分钟
  price: number
  currency: 'USD' | 'ETH'    // 【Assumption】支持法币和加密货币
}

interface Pricing {
  id: number
  name: string               // 如 "基础套餐"
  price: number
  currency: 'USD' | 'ETH'
  unit: 'hour' | 'job' | 'day'
  description?: string
}

interface Availability {
  timezone: string
  schedule: WeeklySchedule   // 【Assumption】周期性可用时间
  exceptions: DateException[] // 特殊日期
}

interface WeeklySchedule {
  monday: TimeSlot[]
  tuesday: TimeSlot[]
  wednesday: TimeSlot[]
  thursday: TimeSlot[]
  friday: TimeSlot[]
  saturday: TimeSlot[]
  sunday: TimeSlot[]
}

interface TimeSlot {
  start: string              // HH:mm 格式
  end: string
}

interface Location {
  city: string
  country: string
  coordinates?: {
    lat: number
    lng: number
  }
  isRemote: boolean          // 是否支持远程服务
}

// ==================== Booking ====================
interface Booking {
  id: number
  agentId: number            // FK -> Agent
  customerId: number         // FK -> User
  serviceId: number          // FK -> Service
  status: BookingStatus
  scheduledAt: string        // ISO datetime
  duration: number           // 分钟
  price: number
  currency: 'USD' | 'ETH'
  notes?: string
  cancellationReason?: string
  payment?: Payment
  createdAt: string
  updatedAt: string
}

type BookingStatus =
  | 'pending'       // 等待代理人确认
  | 'confirmed'     // 已确认
  | 'in_progress'   // 进行中
  | 'completed'     // 已完成
  | 'cancelled'     // 已取消
  | 'disputed'      // 争议中【Assumption】

// ==================== Review ====================
interface Review {
  id: number
  bookingId: number          // FK -> Booking
  reviewerId: number         // FK -> User
  revieweeId: number         // FK -> User
  rating: number             // 1-5
  comment: string
  response?: string          // 被评价者回复
  isPublic: boolean
  createdAt: string
  updatedAt: string
}

// ==================== Message ====================
interface Message {
  id: number
  conversationId: number     // FK -> Conversation
  senderId: number           // FK -> User
  content: string
  type: 'text' | 'image' | 'file' | 'system'
  isRead: boolean
  createdAt: string
}

interface Conversation {
  id: number
  participants: number[]     // User IDs
  bookingId?: number         // 关联预约
  lastMessage?: Message
  unreadCount: number
  createdAt: string
  updatedAt: string
}

// ==================== Payment ====================
interface Payment {
  id: number
  bookingId: number          // FK -> Booking
  amount: number
  currency: 'USD' | 'ETH'
  status: PaymentStatus
  method: PaymentMethod
  transactionHash?: string   // 链上交易哈希
  platformFee: number        // 平台佣金【Assumption】5%
  providerFee: number        // 支付渠道费用
  paidAt?: string
  refundedAt?: string
  createdAt: string
}

type PaymentStatus =
  | 'pending'
  | 'processing'
  | 'completed'
  | 'failed'
  | 'refunded'
  | 'partially_refunded'

type PaymentMethod =
  | 'crypto_wallet'          // MetaMask/Web3
  | 'stripe'                 // 【Assumption】集成 Stripe
  | 'platform_balance'       // 【Assumption】平台余额

// ==================== Notification ====================
interface Notification {
  id: number
  userId: number
  type: NotificationType
  title: string
  message: string
  data?: Record<string, any> // 相关数据
  isRead: boolean
  createdAt: string
}

type NotificationType =
  | 'booking_request'
  | 'booking_confirmed'
  | 'booking_cancelled'
  | 'booking_completed'
  | 'new_message'
  | 'new_review'
  | 'payment_received'
  | 'payment_failed'
```

### 3.2 关系图

```
User (1) ────< (N) Agent           // 一个用户可创建多个代理人资料
User (1) ────< (N) Booking         // 作为客户
Agent (1) ────< (N) Booking        // 作为服务提供者
Booking (1) ────< (N) Review       // 一次预约可有双方评价
User (1) ────< (N) Conversation    // 通过 participants
Conversation (1) ────< (N) Message
Booking (1) ──── (0..1) Payment
User (1) ────< (N) Notification
```

### 3.3 数据约束

| 字段 | 约束 |
|------|------|
| User.walletAddress | unique, lowercase, 0x开头42位 |
| User.email | unique, valid email format |
| Agent.rating | 0 <= rating <= 5, 默认 0 |
| Service.price | > 0 |
| Booking.scheduledAt | > now (创建时) |
| Review.rating | 1 <= rating <= 5 |
| Payment.platformFee | 【Assumption】amount * 0.05 |

## 四、API 契约

### 4.1 认证 API (已实现)

```yaml
# 获取签名 Nonce
GET /auth/nonce
  Query: { walletAddress: string }
  Response: { nonce: string, message: string }
  Errors: 400 (invalid address)

# 登录
POST /auth/login
  Body: { walletAddress: string, signature: string }
  Response: { access_token: string, user: User }
  Errors: 400 (invalid signature), 401 (auth failed)

# 获取当前用户
GET /auth/profile
  Headers: Authorization: Bearer <token>
  Response: User
  Errors: 401 (unauthorized)
```

### 4.2 用户 API

```yaml
# 更新用户资料
PATCH /users/me
  Headers: Authorization
  Body: { name?, email?, avatar?, bio? }
  Response: User
  Errors: 400 (validation), 401, 409 (email conflict)

# 获取用户公开资料
GET /users/:id
  Response: PublicUser (不含 email)
  Errors: 404 (not found)
```

### 4.3 Agent API

```yaml
# 获取 Agent 列表
GET /agents
  Query: {
    category?: string
    location?: string
    minRating?: number
    minPrice?: number
    maxPrice?: number
    sortBy?: 'rating' | 'price' | 'reviews' | 'created'
    sortOrder?: 'asc' | 'desc'
    page?: number (default: 1)
    limit?: number (default: 20, max: 50)
    search?: string
  }
  Response: { data: Agent[], total: number, page: number, limit: number }
  Errors: 400 (invalid query)

# 获取 Agent 详情
GET /agents/:id
  Response: Agent (含 user 关联)
  Errors: 404

# 创建 Agent
POST /agents
  Headers: Authorization
  Body: CreateAgentDTO
  Response: Agent
  Errors: 400, 401, 403 (已有 agent)【Assumption】

# 更新 Agent
PATCH /agents/:id
  Headers: Authorization
  Body: UpdateAgentDTO
  Response: Agent
  Errors: 400, 401, 403 (not owner), 404

# 删除 Agent
DELETE /agents/:id
  Headers: Authorization
  Response: { success: true }
  Errors: 401, 403, 404

# 获取我的 Agent 列表
GET /agents/me
  Headers: Authorization
  Response: Agent[]
  Errors: 401
```

### 4.4 Booking API

```yaml
# 创建预约请求
POST /bookings
  Headers: Authorization
  Body: {
    agentId: number
    serviceId: number
    scheduledAt: string (ISO)

  }
  Response: Booking
  Errors: 400, 401, 404 (agent/service), 409 (时间冲突)

  Headers: Authorization
  Query: {
    role?: 'customer' | 'agent'
    status?: BookingStatus

    limit?: number
  }
  Response: { data: Booking[], total: number }
  Errors: 401

# 获取预约详情
GET /bookings/:id
  Headers: Authorization
  Response: Booking (含 agent, customer 关联)
  Errors: 401, 403 (not participant), 404

# 更新预约状态 (Agent 操作)
PATCH /bookings/:id/status
  Headers: Authorization
  Body: { status: 'confirmed' | 'cancelled', reason?: string }
  Response: Booking
  Errors: 400 (invalid transition), 401, 403, 404

# 取消预约 (Customer 操作)
POST /bookings/:id/cancel
  Headers: Authorization
  Body: { reason?: string }

  Errors: 400 (cannot cancel), 401, 403, 404

# 完成预约
POST /bookings/:id/complete
  Headers: Authorization

  Errors: 400 (invalid status), 401, 403, 404
```

### 5.3 缓存策略

| 数据类型 | staleTime | gcTime | 策略说明 |
|----------|-----------|--------|---------|
| Agent 列表 | 5min | 30min | 允许短暂过期，后台刷新 |
| Agent 详情 | 10min | 1h | 相对稳定，可缓存较长 |
| Booking 列表 | 0 | 10min | 实时性要求高 |
| Messages | 0 | 5min | 实时性要求高，配合 WebSocket |
| Categories | 24h | 7d | 静态数据，长期缓存 |
| 用户资料 | 15min | 1h | 中等实时性 |


```typescript
// 路由守卫 Hook
const useAuthGuard = (requiredRole?: UserRole) => {
  const { isAuthenticated, user } = useAuth()
  const navigate = useNavigate()

  useEffect(() => {
    if (!isAuthenticated) {
      navigate('/') // 或触发登录弹窗
    }
    if (requiredRole && user?.role !== requiredRole) {
      navigate('/403')
    }
  }, [isAuthenticated, user, requiredRole])
}

// 条件渲染组件
const AuthGuard: FC<{ children: ReactNode; fallback?: ReactNode }> = ({
  children,
  fallback = <LoginPrompt />
}) => {
  const { isAuthenticated } = useAuth()
  return isAuthenticated ? <>{children}</> : <>{fallback}</>
}
```

## 十、假设汇总 【Assumption】

1. **用户角色**: 用户可同时是客户和代理人 (`role: 'both'`)
2. **支付方式**: 支持 Web3 钱包支付 + Stripe 法币支付
3. **平台佣金**: 每笔交易收取 5% 平台服务费
4. **响应时间**: Agent 资料中显示 "< 1 hour" 等响应时间描述
5. **争议处理**: Booking 状态支持 'disputed' 争议状态
6. **单 Agent 限制**: 每个用户可创建多个 Agent 资料
7. **实时通信**: 使用 WebSocket 实现消息和通知推送
8. **语言支持**: 初期仅支持中文，预留国际化接口

## 十一、验证方式

### 端到端测试清单

1. **Auth Flow**: 钱包连接 → 签名 → 登录成功 → Profile 显示
2. **Agent Flow**: 创建 Agent → 列表展示 → 详情页 → 编辑 → 删除
3. **Booking Flow**: 选择服务 → 选择时间 → 提交预约 → Agent 确认 → 完成
4. **Payment Flow**: 确认支付 → 选择方式 → Web3 签名 → 支付成功
5. **Review Flow**: 完成预约后 → 发表评价 → 评价展示 → Agent 回复
6. **Message Flow**: 发起会话 → 发送消息 → 接收消息 → 标记已读
